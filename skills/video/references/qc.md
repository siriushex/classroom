# Проверка качества видео

## До полного рендера

1. Сделай media inventory: путь, источник, права/лицензия, длительность, fps, разрешение, аудио, назначение. Дефектные записи проверь плотной последовательностью кадров; редкая выборка 1 кадр/2 секунды пропускает рывки.
2. Согласованные параметры внеси в [plan.json](../templates/plan.json). Для шахмат есть [chess-plan.json](../templates/chess-plan.json). Укажи каждый cut, intentional hold/black и text block. Данные должны описывать настоящий монтаж, не скрывать найденные ошибки. Safe area зависит от площадки, формата и текущего UI; числа в шаблоне являются отправной точкой.
3. Проверь исходную игру/интерфейс без изменения её кода, если запрос разрешает только видео. Ищи перерисовку всей доски, смену высоты/отступов, исчезновение шрифтов, неправильно обрезанный crop и задержки захвата. Зафиксируй замеры.
4. Сделай 1–3 секунды пробного рендера проблемного участка. Переход, крупный текст и быстрый ход требуют теста именно в целевых разрешении и fps.
5. Проверь first/last frame сцен и final branded/no-text card. Для зависимых Remotion пакетов используй одну совместимую фиксированную версию. При пропадании объектов в параллельном capture сначала воспроизведи проблему с одной страницей захвата; не повышай concurrency без проверки.

## После экспорта

```sh
python3 /absolute/skill-dir/scripts/video_qc.py /absolute/video.mp4 \
  --plan /absolute/plan.json --report /absolute/new-qc.json
```

Скрипт не редактирует исходный ролик и не устанавливает пакеты. Требует Python 3.9+, FFmpeg и FFprobe в PATH. Существующий отчёт не перезаписывает. Полностью декодирует файл, читает таймкоды каждого кадра и анализирует все кадры на уменьшенной серой сетке.

| Код | Значение | Действие |
|---|---|---|
| 0 | technical_pass | Продолжить визуальный и звуковой просмотр |
| 2 | fail | Исправить конкретную ошибку и проверить новый экспорт |
| 3 | review | Просмотреть перечисленные интервалы; документировать результат |

Проверяются длительность, fps, размеры, число кадров, наличие аудио, порядок/интервалы таймкодов, декодирование, чёрные участки, почти одинаковые соседние кадры, яркостное мерцание и крупные визуальные изменения. Декларированные строки проверяются на запрещённый бренд, no-text, время показа и границы safe area.

**Ограничения:** declared text/box не заменяют OCR и измерение настоящих glyph bounds. Серые уменьшенные кадры пропускают локальные дефекты, изменения только цвета и мелкие исчезающие элементы. Повтор кадра может быть правильной паузой. VFR не доказывает frame drop. Скрипт не измеряет синхронизацию речи и не определяет художественное качество. Technical_pass никогда не называется окончательной визуальной проверкой.

Отдельно смотри полный ролик на нормальной скорости и каждый flagged участок с кадрами ±3 вокруг дефекта. Для доски измеряй её границы/ROI и положения фигур: неподвижная доска с телепортирующей фигурой может пройти глобальную эвристику.

## Визуальное принятие

- Каждый cut сохраняет намеренный объект внимания и направление. Нет случайного исчезновения, повторного начала движения или склейки на полуслове.
- Камера и layout не скачут. Плавность доказана просмотром/траекториями, а не только fps или количеством уникальных кадров.
- Шрифты загружены, строки не обрезаны, кириллица верна, текст читается на телефоне. Слова из неверной локализации отсутствуют в кадрах.
- Нет случайных UI, cursor, selection, loading overlays и встроенных AI-надписей в no-text.
- Голос, музыка, контакты и эффекты синхронны; конец не обрывается. Если версия тихая, аудиопотока действительно нет.
- Для 9:16 и 16:9 выполнен отдельный композиционный монтаж. Адаптацию с blur-полями обозначай адаптацией, не отдельной AI-генерацией.

На 0–5 оцени фокус/композицию, непрерывность движения, монтаж/ритм, визуальную систему, соответствие заданию. Для каждой оценки дай наблюдаемое основание. Это редакторская оценка, не машинная метрика: ноль в любой категории требует исправления, не усреднения. Если текст/звук присутствуют, их проверка обязательна отдельно.

## Отчёт

Сохрани exact output path, SHA-256, параметры, проверенные интервалы, скриншоты/контактный лист, найденные дефекты, исправления и ограничения. Технический отчёт и человеческие проверки дополняют друг друга. Загруженный файл проверяй на конечной площадке без повторного рендера неизменённого файла. Сохраняй старые версии, если пользователь просит варианты.
